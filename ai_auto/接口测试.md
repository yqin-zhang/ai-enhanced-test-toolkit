# 设备管理接口测试用例

被测服务：`test_projects/device_server.py`  
Base URL：`http://127.0.0.1:8000`  
文档页：`http://127.0.0.1:8000/docs`

约定：

- 正向业务成功：HTTP 200，body 含 `code = 0`
- 业务错误：400 / 404 / 500，body 含 `detail`
- 入参校验失败（Pydantic）：422
- 方法不允许：405
- 状态枚举仅允许：`online` / `offline` / `fault`
- 注册字段约束：`device_id` 1~64，`device_name` 1~128，`device_type` 1~64
- 列表接口 `data` 为数组；单条查询 `data` 为对象

建议：需要设备的用例自行注册/清理（夹具），不要依赖跨文件执行顺序。

约定补充：`GET /device/{device_id}`、`DELETE /device/{device_id}` 会吃掉 `/device/` 后任意一段。因此 `GET/DELETE /device/lists` 是「设备不存在」，不是框架 `Not Found`；`Not Found` 只出现在前缀都不匹配的路径（如 `/devices/list`）。列表的 405 只测 POST/PUT，不要测 DELETE `/device/list`。注册的 405 不要测 GET `/device/register`。

---

## 1. POST `/device/register` 注册设备

| 编号 | 类型 | 场景 | 前置 | 请求 | 预期 |
| --- | --- | --- | --- | --- | --- |
| REG-P01 | 正向 | 注册成功 | 该 `device_id` 不存在 | body：`device_id=dev002`，`device_name=红外传感器`，`device_type=sensor` | 200；`code=0`；`msg=注册成功`；`data.device_id=dev002`；库中默认 `status=offline` |
| REG-N01 | 异常 | 重复注册 | 已存在相同 `device_id` | 再 POST 同一 id | 400；`detail` 含「设备ID已存在，重复注册」 |
| REG-N02 | 异常 | 缺少 `device_id` | 无 | 只传 name、type | 422 |
| REG-N03 | 异常 | 缺少 `device_name` | 无 | 只传 id、type | 422 |
| REG-N04 | 异常 | 缺少 `device_type` | 无 | 只传 id、name | 422 |
| REG-N05 | 异常 | 空对象 | 无 | body `{}` | 422 |
| REG-N06 | 异常 | 必填为空串 | 无 | id / name / type 任一为 `""` | 422 |
| REG-N07 | 边界 | 超长 | 无 | id>64 或 name>128 或 type>64 | 422 |
| REG-N08 | 异常 | 未传 body | 无 | 不要带 `json=` / `data=` | 422；`loc=["body"]`；`input=null` |
| REG-N09 | 异常 | body 不是 JSON 对象 | 无 | `json=` 发出去是合法 JSON 字符串，不是对象 | 422 |
| REG-N10 | 异常 | JSON 语法错误 | 无 | 非法 JSON 原文（`data=` 发，不要 `json=`） | 422；`type=json_invalid` |
| REG-N11 | 异常 | 错误方法 | 无 | PUT/PATCH 打该路径 | 405；不要 GET，会被 `{device_id}` 吃成查询 404 |

本接口用例合计 12 条。

注意：

- REG-N02 / N03 / N04 / N05 / N06 / N07 都是 422，测试里可参数化合并；文档仍按场景分开。
- REG-N05（`{}`）和 REG-N08（整段 body 没传）都是 422，但 `loc` / `input` 不同，不要合成一条。
- REG-N09（合法 JSON 但不是对象）和 REG-N10（语法错误）不要合成一条。
- 语法错误必须 `data=` 发原文；`json=` 会先被序列化，发不出去非法 JSON。

## 2. GET `/device/list` 设备列表

| 编号 | 类型 | 场景 | 前置 | 请求 | 预期 |
| --- | --- | --- | --- | --- | --- |
| LIST-P01 | 正向 | 列表包含已注册设备 | 已注册 `dev002` | GET `/device/list` | 200；`code=0`；`data` 为列表；存在 `device_id=dev002` 且 name/type 与注册一致 |
| LIST-N01 | 异常 | 错误方法 | 无 | POST/PUT `/device/list` | 405；不要 DELETE，会被当成删 id=`list`，返回 404「设备不存在」 |
| LIST-N02 | 回归 | 路径不被 `{device_id}` 抢占 | 无 | GET `/device/list` | 不能 404；`data` 必须是数组 |
| LIST-N03 | 异常 | 错路径 | 无 | GET `/device/lists`；GET `/devices/list` | 前者 404「设备不存在」；后者 404 `Not Found` |

本接口用例合计 4 条。

说明：不要写死 `data[1]`，列表长度和顺序不保证；按 `device_id` 查找对应项。

## 3. GET `/device/{device_id}` 查询单个设备

| 编号 | 类型 | 场景 | 前置 | 请求 | 预期 |
| --- | --- | --- | --- | --- | --- |
| GET-P01 | 正向 | 查询已注册设备 | 已注册 `dev002` | GET `/device/dev002` | 200；`code=0`；`data.device_id/name/type` 与注册一致；`data` 为对象 |
| GET-N01 | 异常 | ID 不存在 | 无 | GET 从未注册的 id | 404；`detail=设备不存在` |
| GET-N02 | 异常 | 删除后再查 | 该 id 刚被删除 | GET 同一 id | 404；`detail=设备不存在` |
| GET-N03 | 异常 | 空路径 | 无 | GET `/device/` | 404；`detail=Not Found` |
| GET-N04 | 异常 | 错误方法 | 无 | POST/PUT 打查询地址 | 405 |
| GET-N05 | 异常 | 错路径 | 无 | GET `/device/{id}/xxx` | 404；`detail=Not Found`（不是「设备不存在」） |

本接口用例合计 6 条。

## 4. PUT `/device/{device_id}/status` 修改设备状态

| 编号 | 类型 | 场景 | 前置 | 请求 | 预期 |
| --- | --- | --- | --- | --- | --- |
| ST-P01 | 正向 | 改为合法状态 | 已存在设备 | PUT，分别测 `offline` / `online` / `fault` | 200；`code=0`；`msg=状态更新成功`；再 GET，`status` 已变且与改前不同 |
| ST-N01 | 异常 | 设备不存在 | id 未注册 | 合法 status | 404；`detail=设备不存在` |
| ST-N02 | 异常 | 删除后再改 | 该 id 已删除 | 合法 status | 404；`detail=设备不存在` |
| ST-N03 | 异常 | 非法状态 | 设备存在 | `busy` / `unknown` | 400；`detail` 含「非法状态」 |
| ST-N04 | 异常 | 大小写不匹配 | 设备存在 | `ONLINE` / `Offline` | 400；`detail` 含「非法状态」 |
| ST-N05 | 异常 | 空串状态 | 设备存在 | `"status":""` | 400（空串不在允许列表，不是 422） |
| ST-N06 | 异常 | 缺少 `status` | 设备存在 | body `{}` | 422；`loc=["body","status"]`；`input={}` |
| ST-N07 | 异常 | 未传 body | 设备存在 | 不要带 `json=` / `data=` | 422；`loc=["body"]`；`input=null` |
| ST-N08 | 异常 | 类型错误 | 设备存在 | `status` 为数字或 `null` | 422；`type=string_type`；`msg` 含「valid string」 |
| ST-N09 | 异常 | 语法错误 | 设备存在 | 非法 JSON 原文（`data=` 发，不要 `json=`） | 422；`type=json_invalid`；`msg=JSON decode error` |
| ST-N10 | 异常 | 错误方法 | 无 | GET/POST 打 status 地址 | 405；`detail=Method Not Allowed` |

本接口用例合计 11 条。

注意：

- 路径中的 `{device_id}` 必须与注册 id 一致（例如不要注册 `dev002` 却改 `dev001`）。
- 注册默认 `status=offline`。测改成 `offline` 时，须先改成其他合法值再改回来，否则 GET 仍是默认值，证明不了「已变」。
- ST-N03 / N04 / N05 走同一段业务校验，测试里可参数化合并；文档仍按场景分开。
- ST-N06（`{}` 缺字段）和 ST-N07（整段 body 没传）都是 422，但 `loc` / `input` 不同，不要合成一条。
- 语法错误必须 `data=` 发原文；`json=` 会先被序列化，发不出去非法 JSON。

## 5. DELETE `/device/{device_id}` 删除设备

| 编号 | 类型 | 场景 | 前置 | 请求 | 预期 |
| --- | --- | --- | --- | --- | --- |
| DEL-P01 | 正向 | 删除成功 | 已存在 `dev002` | DELETE `/device/dev002` | 200；`code=0`；`msg=删除成功`；再 GET 为 404；库中无该记录 |
| DEL-N01 | 异常 | 删除不存在 | 从未注册 | DELETE 任意不存在 id | 404；`detail=设备不存在` |
| DEL-N02 | 异常 | 重复删除 | 刚删除成功 | 再 DELETE 同一 id | 404 |
| DEL-N03 | 异常 | 空路径 | 无 | DELETE `/device/` | 404；`detail=Not Found` |
| DEL-N04 | 异常 | 错路径 | 无 | DELETE `/device/{id}/delete` | 404；`detail=Not Found` |

本接口用例合计 5 条。
